# AI Dash portfolio and publication review

Reviewed 25 November 2026. AI Dash adds a useful application to this portfolio:
configurable AI briefings with evidence, editorial policy and durable delivery.
Its incremental value is strongest as a working use of the gateway and orchestration
ideas already demonstrated elsewhere. It is a plausible niche tool for technical
readers, not yet evidence of a differentiated commercial product or an established
user community.

The repository was verified private. No credential was detected in the audited
AI Dash source/history or comparator documentation. This is scoped repository
inspection, not proof that an account has never been compromised.

The strongest additions are the domain work: source-specific evidence recovery,
timestamp semantics, impact scoring, distinct report policies, quiet-day behavior,
durable delivery diagnostics and current-news recovery. Windmill, Telegram and
LLM ranking alone overlap heavily with DailyDash and do not create a strong moat.
Keeping the two applications independent is useful for operation and policy, but
copying infrastructure into more repositories should not be the selling point.

## Who might be interested

The most plausible audience is an AI engineer, researcher or technical lead who
already reads these sources and wants a self-hosted Telegram briefing with editable
source lists, thresholds and schedules. Engineers assessing the portfolio may
also value the complete runtime, failure handling and inspectable evidence.
These are audience hypotheses, not observed leads or verified willingness to pay.

The main adoption friction is setup: an application checkout, multiple Windmill
services, a separate gateway, Telegram provisioning and mandatory Reddit mounts
in the current Compose template. There is no browser dashboard, hosted onboarding,
multi-user subscription management or feedback-driven personalization. Nitter
availability and subjective ranking quality also limit the promise.

A small public reference application is a reasonable eventual positioning. Before
claiming wider demand, show a sanitized actual digest and ask a few intended readers
to use it for a week. Measure stories they read/save, duplicates, missed important
items and configuration effort. An unproven SaaS positioning would add expectations
that this repository does not currently meet. Publication itself remains a separate
choice; visibility was not changed by this review.

## Credential and account exposure audit

The inspection included tracked and nonignored working files, all documentation
and evidence, scripts, configuration, workflows, build definitions and local ignored
runtime/evaluation data. Gitleaks 8.30.1 scanned all available branches/reflogs and
GitHub pull-request head refs 1–29. Two locally dangling commits were also included
in the earlier history pass. It found no credential in history. The working-data
scan flagged two ranking `event_key` strings in ignored evaluation JSON; inspection
identified event slugs, not API keys. No suppression was added for these matches.

The fetched public READMEs/architecture documents also had no detected credential.
That is not a complete secret audit of every public repository's source/history,
GitHub Actions artifact, external host, account session or provider account.
No provider keys were tested and no account audit log was inspected.

A current PyPI advisory check found no known vulnerability in 33 resolved
third-party distributions. The local `ai-dash` distribution was skipped because it
is not a PyPI release. This does not cover the OS, PostgreSQL, Windmill base image
or the separately deployed gateway.

No private runtime paths appeared in the built wheel or source-distribution member
inventory. Runtime state stays outside the deployment checkout. Telegram errors
omit token-bearing URLs, and the Reddit client refuses redirects for its fixed
credential-bearing endpoints. None of the findings established a credential that
needs revocation. If an actual exposed key is discovered later, revoke it first;
removing a file or making a repository private does not invalidate a credential.

## Findings and work performed

| Priority | Finding | Resolution or remaining action |
| --- | --- | --- |
| P1 | Feed/HTML/Nitter/YouTube requests followed redirects without public-address enforcement; hydration separately resolved DNS before HTTP connection | Fixed in PR 29: checked global addresses, pinned connections, preserved Host/TLS identity, checked each redirect and disabled environment proxies for public fetching |
| P1 | Ordinary sources buffered the body before checking size; Nitter had no response-size check | Fixed: streamed byte limits for all these source paths, 12 MB source / 2 MB article limits; identity encoding with compression rejection before decoding |
| P2 | Deployment/provenance docs contained unnecessary SSH aliases, a machine identifier, bot identity, provider generation IDs and private evidence locations | Removed from current source-facing docs; original historical text remains in Git |
| P2 | Reddit collected successfully but rejected all 18 fresh posts; all 14 hydration attempts scraped blocked Reddit pages, and blog-oriented ranking demanded independent proof | Added a community-specific prompt/gates, retained crosspost text, hydrated primary links and required summaries to distinguish claims from facts |
| P2 | Current source instructions were mixed with retired paid-X/shared-runtime/catch-up behavior, old model settings and stale test/source counts | Added current documentation index/architecture/operations, labeled dated investigations, corrected gateway ownership and current report overrides |
| P2 | No automatic credential scan in CI; `.env` variants and private key/profile names lacked explicit excludes | Added history/checkout scanning with a checksum-verified pinned binary, read-only workflow permissions and expanded Git/build-context excludes |
| P2 | Local editable-install hooks could leave repeat checks importing no project package | Gate now reinstalls the current wheel and runs commands without implicit resynchronization |
| P2 | Smoke check required the SSH user to read a gateway token that is intentionally private to the worker | Corrected the check to run inside the worker; included the orchestration worker in service checks |
| P2 | A partially delivered edition reserves all its stories in history after any part is sent | Remains: an unsent story can be suppressed for the history horizon. Per-story acknowledgement requires a separate state/delivery change |
| P2 | Worker image runs as root and the stack is for a trusted single operator | Remains: no general multi-tenant isolation claim; hardening requires Windmill-compatible validation |
| P2 | Current Compose unconditionally mounts Reddit credentials | Remains: document the requirement; a key-free/optional-Reddit deployment profile would reduce onboarding friction |
| P3 | Thin README and absent current architecture obscured functionality and cost boundaries, including the new YouTube report | Expanded README and added all four current architecture guides; upload listings are explicitly not video summaries |

The original operator identifiers are low-sensitivity infrastructure metadata, not
login credentials, and this repository remains private. Current-file cleanup does
not remove them from old commits or PR diffs. If keeping those identifiers out of
any future public release is required, review a clean public export or a deliberate
history-cleanup plan before changing visibility. No history rewrite or force push
was performed.

## Verification and deployment evidence

PR 29 integrated the existing cadence/input/delivery/Reddit recovery branch with
the fetching fixes, preserving the already-merged YouTube report. Its complete
quality gate and GitHub CI passed: 128 offline tests, Ruff, config validation,
generated workflows and source/wheel builds. Free live probes through the hardened
transport successfully fetched OpenAI RSS, YouTube and Nitter. These establish
those requests worked at the time, not continuous availability or complete coverage.

The VPS was switched to merged main at `e95f546`. Installed application module
hashes matched source. SQLite integrity passed; all twelve schedule states,
109 persisted editions and 118 acknowledged messages were preserved. Runtime
credential hashes matched the private baseline and other project/gateway containers
were not recreated. Authenticated gateway readiness passed from the worker. A
private SQLite backup and before/after checks were saved outside source.

No manual paid inference or Telegram send was used for these deployment checks.
Normal scheduled operation remains enabled. The original local edits were already
present in the integrated recovery branch; a safety stash preserves their initial
snapshot and the original checkout was fast-forwarded to clean main. The follow-up adds the community-ranking/evidence repair, its regression coverage,
current docs and secret-scanning CI, and corrects the local quality gate and
deployment smoke checker. Its offline suite passes 137 tests.
